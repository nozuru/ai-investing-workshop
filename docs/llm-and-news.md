# LLMやニュースを戦略に使う

戦略の判断にLLMやニュースを使いたいチーム向けの資料です。使わなくても構いません。
接続先とキーは当日配ります。キーをコードに直接書かず、`.env` ファイルに記載してください。`.env` はGitの管理対象に含めません。

## ローカルLLM

会場のローカルLLMは、OpenAI互換のAPIとして `litellm` から呼び出せます。
必要なパッケージは `uv add litellm diskcache` で入ります（litellm 1.109.1、diskcache 5.6.3でキャッシュの動作を確認済み）。

```python
import os

import diskcache
import litellm

# 同じ質問への応答をフォルダに保存する。2回目以降の実行ではLLMを呼ばない。
cache = diskcache.Cache("llm_cache")


@cache.memoize()
def ask(prompt: str) -> str:
    response = litellm.completion(
        model=f"openai/{os.environ['WORKSHOP_LLM_MODEL']}",
        api_base=os.environ["WORKSHOP_LLM_BASE_URL"],
        api_key=os.environ["WORKSHOP_LLM_API_KEY"],
        messages=[{"role": "user", "content": prompt}],
        timeout=120,
    )
    return response.choices[0].message.content
```

上記のコードのように `diskcache` による応答の保存（キャッシュ）を有効にしておくと、コードを直して再実行しても、同じ質問であればLLMを呼び出さずに保存済みの応答を再利用します。

### 処理速度の目安

呼び出す頻度や回数に決まりはありません。戦略に必要な使い方を、そのまま実装してください。

会場のLLMは全チームで共有しており、同時接続数は最大10、1接続あたりの生成速度は毎秒30トークンほどです。
呼び出し回数が多い戦略では、時間内に全期間を回し切れないことがあります。途中で止まっても、そこまでの経過を見せられるように実装してください。

- **古い日付から順に進める**: 判断日を古い順に処理し、現在どの日付まで進んだかを画面に表示します。
- **判断のたびにすべて記録する**: LLMを1回呼び出すごとに、判断日、渡した内容、応答、その結果の売買、その日までの資産額を `llm_log.jsonl` に1行ずつ追記します。資産推移の `equity.png` も、判断日が1つ進むたびに更新します。
- **止めても続きから再開できるようにする**: 応答は上記のとおりキャッシュされるため、再実行すれば処理済みの分はLLMを呼び出さずに進みます。
- **時間切れのとき**: 進んだところまでの結果で発表します。記録から成績の表を作り、`results.md` の「期間」には、実際に処理できた日付までを記載してください。

### 先読みの落とし穴

LLMを使う戦略には特有の落とし穴があります。
モデルは学習した時点までの相場を知っているので、その期間のバックテストは実力以上に成績が良く出てしまいます。
最終実行の期間がモデルの学習時期より後であれば、そこで本当の差が見えます。

## ニュース（モモンガサーチ）

日本企業の開示情報とニュースを、日付で区切って取得できます。

- 接続先: `https://api.momongasearch.com/v1`
- 認証: `Authorization: Bearer <キー>` ヘッダー
- ニュース一覧: `GET /news`。銘柄コード（`security_codes`）と期間（`timeline_since`、`timeline_until`）で絞ります。
- 返ってくるのは見出し（`title`）と1〜3文の要約（`body`）です。記事の全文ではありません。

### ニュースの取得と保存

- **バックテストでの判断日**: 判断する日より後のニュースを取得しないよう、`timeline_until` に判断日を必ず指定します。
- **更新時刻による絞り込み**: 期間の絞り込みは更新時刻に対して行われます。あとから改訂されたニュースは、最初の公表日より後の日付として取得される点に注意してください。
- **ファイルへの保存**: 取得したニュースはファイルに保存し、同じ期間のデータを2回取得しないようにします。

引数の正確な書き方は、当日配る資料か、コーディングAIに登録したMomonga Search MCPで確認してください。
